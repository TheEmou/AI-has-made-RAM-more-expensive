## 经验：无头 Chrome 做视觉自检的正确姿势

- 本机 bash 需要先 `export PATH="/usr/bin:/bin:$PATH"`，否则 `date`/`dirname` 等命令找不到。
- 用本机 `C:\Program Files\Google\Chrome\Application\chrome.exe` 的 `--headless=new --screenshot` 即可逐屏截图，无需安装 agent-browser。
- **URL hash 跳转在无头模式下不可靠**：截图仍停在页顶或落在空白区。可靠做法是把目标 `<section>` 单独抽成一个临时页面（其余 section 用正则删掉），再截图。
- 进场动画（opacity 0 → 1 的 transition）会被截到中间帧，导致画面发灰甚至全白。校验页里必须注入 `transition:none !important` 并补 `.in` 类。
- Windows 下 Chrome 有最小窗口宽度（约 485 CSS px），`--window-size=390` 拿不到 390 的视口。要测真机宽度，用 `--force-device-scale-factor=1.244 --window-size=485,...` 换算出 390 CSS px。
- 判断横向溢出不要靠肉眼看截图，直接在页面里注入脚本比较 `documentElement.scrollWidth` 与 `clientWidth`，再用 `--dump-dom` 读结果。

## 踩到的坑（下次直接避开）

1. 柱状图用「列高百分比」当柱高基准，会被数值标签挤爆 → 给柱体套一层 `flex:1 1 auto; min-height:0` 的 track，百分比才对 track 生效。
2. `grid` + `gap:1px` + 背景色当分割线的卡片墙，末行不满时会露出整片灰底 → 卡片数量固定为 6 张时直接用 `repeat(3, 1fr)` 保证铺满，并在窄屏降为 2 列。
3. 卡片右上角的绝对定位角标会压住正文首行 → 改成流内 `inline-block`。
4. 居中垂直排布的 Hero 里，内容一旦超过 100vh，跑马灯就被顶出首屏 → 用无头截图量一遍再调 padding。
